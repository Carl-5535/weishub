# v1 真机冒烟清单（手动执行，非 CI）

> 前置：已完成 `npm run build && npm install -g ./packages/weishub`；手机微信可用。
> 记录方式：每步通过打勾，异常写明现象与时间。

## 1. 启动与扫码登录

- [ ] 终端运行 `weishub`（无凭据时）输出「尚未登录微信：请用手机微信扫码…」与一个 `http://127.0.0.1:<port>/?token=<token>` 面板地址；
- [ ] 浏览器打开面板地址能见到登录/聊天面板（无 token 或错 token 应 401）；
- [ ] 面板点击扫码，手机微信扫码确认；
- [ ] 终端输出「扫码成功，正在启动微枢…」→「微枢已启动。面板地址：…」，服务保持常驻。

（替代路径）`weishub login`：终端直接打印二维码文本，扫码确认后输出「登录成功」，再 `weishub` 启动应不再要求扫码。

## 2. 微信入站 → agent 回复

- [ ] 手机微信给机器人发送 `你好`；
- [ ] 收到「已绑定 agent「claude」，直接发消息即可开始。」及后续回复；
- [ ] 再发一句任务（如「帮我看看 ~/weishub-workspace 里有什么文件」），确认 agent 正常回复且无报错。

## 3. wx 出站推送

- [ ] 另开终端：`wx send "test"` → 手机微信收到「test」；
- [ ] `wx send --image <任意 png 路径>` → 微信收到图片；
- [ ] `wx status` → 输出「微信登录：已登录」与发件箱条数；
- [ ] （降级验证）`kill` 掉 weishub 进程后再执行 `wx send "x"` → 应报「无法连接…」并退出码 1，不挂死。

## 4. 审批桥（claude，auto 模式）

- [ ] 微信发送一个需要写文件/执行命令的任务（如「在 ~/weishub-workspace 写一个 hello.txt」）；
- [ ] 触发权限请求时微信收到审批提示，回复「同意」→ agent 继续完成；
- [ ] 回复「拒绝」的路径：再触发一次审批，回复「拒绝」→ agent 收到拒绝结果。

## 5. 单实例与重启恢复

- [ ] 再开一个终端跑 `weishub` → 报「另一个 weishub 实例正在运行 (pid=…)」退出；
- [ ] Ctrl-C 停掉服务，重启 `weishub` → 不要求重新扫码，agent 绑定关系保留。

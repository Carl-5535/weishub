## 结果

- 执行日期：2026-10-25
- 结果：**全部通过**。管线、审批桥（同意/拒绝）、出站推送（文本/图片/状态/降级）、单实例锁、重启恢复、真实手机↔微信↔agent 双向闭环全部验证。过程中发现并修复两个真 bug（见下）。
- 备注：出站测试文本与封面图片因首次绑定的服务端黑洞未送达旧绑定；重新扫码后全链路正常。

## 过程中发现并修复的问题（2026-10-25）

1. **审批桥 toolName bug**：`--permission-prompt-tool` 必须传全限定名
   `mcp__weishub-approval__weishub_request_permission`，传裸工具名被 claude 以
   「MCP tool … not found」拒绝。单端测试发现不了（假 agent 不校验）。已修复并真机验证同意/拒绝两条路径。
2. **owner 校验静默拒主**：owner 与去重两个丢弃点原本完全静默，且凭据 userId 与真实会话
   id 存在不同代际的情况（同一微信用户在不同绑定代际拿到不同会话 id，真机实测）。
   修复：两个丢弃点都打 stderr 日志；owner 判定增加「首条私聊消息认领」回退（持久化、
   重新扫码时重置、群聊不认领）。

## 遗留问题 1：绑定在服务端卡死（已解决）

现象与过程：重新扫码（当晚第 2 次绑定）后，出站 sendmessage 全部返回成功但消息从未
投递到手机（「假成功」黑洞），入站在仅送达一条后彻底停止（全新游标 + 健康轮询也收不到），
hub 侧零协议错误。判定为服务端绑定状态损坏，本机无解。

解决：备份旧凭据 → 以占位凭据阻止旧凭据自动迁回 → 重启进扫码等待 → 重新扫码拿到
**全新绑定**（accountId/token 均变，且 userId 恢复为与真实会话一致的代际）→ 手机发
「你好」→ claude 回复送达，全链路闭环。

经验：遇到「发消息没反应 + `wx send` 报 503 但 API 假成功」的组合，直接重新扫码；
若扫码后仍异常，删除 `~/.weishub/account.json` 后重启再扫（避免 binded_redirect
回旧绑定）。

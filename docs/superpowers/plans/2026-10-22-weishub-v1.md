# 微枢 weishub v1 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 独立单进程 hub：微信 iLink 通道 + 自动发现本机无头 agent + 通用适配器 + 微信审批桥接 + `wx` 出站 CLI + 本地 Web 面板。

**Architecture:** npm workspaces monorepo，四包分层：`@weishub/channel-wechat`（微信协议层，自 dsh-wechat-gateway 抽取，零框架依赖）→ `@weishub/core`（agent 注册/适配/调度/审批/通知 API）→ `weishub`（主进程 + Web 面板 + `wx` CLI）→ `@weishub/skills`（Claude Code skill）。hub 单进程独占 iLink 长轮询，agent 以无头 CLI 子进程执行，prompt 走 stdin，状态 JSON 600 权限落盘。

**Tech Stack:** TypeScript（strict）、Node ≥ 20、vitest、npm workspaces。运行时第三方依赖仅 `qrcode`（weishub 包，Web 扫码用）。

**Spec:** `docs/superpowers/specs/2026-10-22-weishub-design.md`（同仓；裁定记录见其 §10）

**参考实现（只读）:** `/Users/carlchen/work/zcode/dsh-wechat-gateway/` —— 其 `src/{ilink,media,store,qrlogin}.ts` 直接迁移适配；`src/index.ts`（1054 行）中的 outbox 投递、审批应答、到期预警逻辑是**抽取重写**的蓝本，不做文件级复制。

## Global Constraints

- Node ≥ 20，TypeScript `strict: true`；所有错误消息与用户可见文案用中文（沿用前身风格）
- 运行时第三方依赖总数 ≤ 5，当前仅 `qrcode`；devDependencies 不限（typescript / vitest / @types/*）
- 单进程；无数据库；所有持久化为 JSON 文件，写入走 `writePrivateJson`（原子 rename + 600 权限）
- 微信 API/CDN 入口必须 HTTPS（回环 HTTP 例外）——迁移代码中已有 `validateApiBase`，不得削弱
- agent prompt 一律经 stdin 传递；适配器命令为 argv 数组，不做 shell 字符串拼接
- v1 仅响应扫码账号本人私聊（owner-only）；白名单逻辑暂不暴露配置
- 权限模式仅 `auto`（默认）| `full`；每聊天独立，`/permission` 切换立即生效
- 工作目录：全局为默认，agent 级覆盖二选一；realpath 越界校验边界 = 生效工作目录
- macOS/Linux 一等公民；Windows best-effort——不允许无平台守卫的 POSIX 专有 API（进程树终止、chmod 处已有守卫模式，照抄）
- 出站消息上限 `maxMessageChars = 3500`；单媒体上限 100 MiB；审批应答词：同意/允许/yes 放行，拒绝/no 驳回，"网页"转交
- 队列上限每聊天 5 条，超限明确拒绝

## Review Focus

规格隐含但单条任务测试不完全覆盖、最容易咬到真实用户的五类输入（每条已把对应测试钉进所属任务）：

1. **超长消息与消息轰炸**——3500 字符切分、每聊天队列 5 条上限、超限明确拒绝而非静默丢弃。→ Task 6 步骤 1（splitText 边界测试）、Task 13 步骤 1（队列上限测试）
2. **agent 未安装或启动失败**——hub 不崩，微信端收到"未发现可用 agent"或任务失败的明确提示。→ Task 9 步骤 1（detect 缺失）、Task 16 步骤 1（spawn 失败回复）
3. **凭据过期时主动推送**——`wx send` 收到明确错误而非挂死；outbox 内容保留待通道恢复。→ Task 15 步骤 1（503 + 保留测试）
4. **双实例/旧插件同时轮询**——第二个 hub 启动即以明确错误退出，不产生消息互相吞吃。→ Task 7 步骤 1（锁文件测试）
5. **失控任务**——超时后进程树（含 agent 再 spawn 的子进程）被杀干净，会话仍可 resume。→ Task 10 步骤 1（孙进程存活测试）
